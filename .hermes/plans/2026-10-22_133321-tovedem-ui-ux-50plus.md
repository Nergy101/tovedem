# Tovedem — 10 UI/UX-verbeteringen voor bezoekers van 50+

## Goal

Make the Tovedem app legible, predictable and easy to navigate for visitors aged
50+, by fixing contrast, text size, navigation depth, page structure, action
buttons, forms, date formatting, feedback and touch targets — without changing
any backend behaviour.

## Current context / assumptions

Verified by reading the repo at commit `f356253` on branch `main`:

- **Stack**: Angular 22, standalone components, Material 3 (`src/tovedem-theme-m3.scss`),
  Bootstrap 5 grid + `mdb-angular-ui-kit`, SCSS, signals, `ngx-toastr`, `luxon`.
- **Baseline is green**: `npm run test` → `TOTAL: 111 SUCCESS`; `npm run lint` →
  `All files pass linting.`
- **Colour tokens are hard-coded in three places** and they disagree:
  `src/variables.scss:4` (`$primary-color: #7db3e8`), `src/styles.scss:16-110`
  (theme blocks), and `src/app/shared/services/theme.service.ts:96-190`
  (imperative `style.setProperty` calls). Any colour change must be made in all
  three or the result is inconsistent.
- **Contrast fails WCAG AA badly** (measured):
  - `#7db3e8` links on white = **2.21:1** (needs 4.5:1)
  - `#7db3e8` links on the card background `#eaf1fc` = **1.95:1**
  - white text on `#7db3e8` primary buttons = **2.21:1**
  This is the single biggest readability problem for older eyes.
- **Body text is 16px** (`src/variables.scss:12`, used in `src/styles.scss:153,167`)
  and there are **43 declared `font-size` values below 14px** across `src/**/*.scss`
  (lowest is `0.7rem` = 11px in `reserveren.component.scss:426`).
- **No user-facing way to enlarge text.** There is a light/dark toggle
  (`navbar.component.html:234-242`) but nothing for size. Browser zoom is the only
  workaround, and our `100vw`/fixed-width rules break under zoom.
- **The top navigation has 10 equally-styled `mat-raised-button` items**
  (`navbar.component.html:37-228`), so nothing looks like *the* primary action, and
  **there is no link to reservation at all** — you must go to Agenda first.
- **Every page title is an unstyled `<div>/<p class="display-1">`** in 20 files;
  only 9 files contain an `<h1>`. Screen readers and "jump to heading" navigation
  therefore find nothing.
- **`/reserveren` is a dead end without a query param**: `reserveren.component.ts:357`
  only loads data `if (this.voorstellingId)`; the template then renders an empty
  card. Same for `saveReservering()` at `:467`, which only shows a toast.
- **Dates leak the English locale**: `datetime.service.ts:formatTableDateTime()`
  returns `"jan. 10, 2026 [19:30]"` in the Dutch UI.
- **Toasts are small and short**: `app.config.ts:64-67` sets only `preventDuplicates`
  and `positionClass`; CSS forces `0.9rem`/`0.85rem` (`styles.scss:1604-1613`).
  Default toastr `timeOut` is 5000ms.
- **Icon buttons are 40px** (Material default) and the navbar SCSS upscales icons
  with `transform: scale(1.5)` (`navbar.component.scss:163-165`) instead of
  increasing the hit area.
- **Contact page uses icon-only buttons** for "Lid worden" / "Steunen"
  (`contact.component.html:25-40`) — a bare icon is not an affordance for this
  audience.
- **Two navigation systems coexist**: the top bar and `sidenav.component.html`
  (423 lines) with different wording for the same destinations
  ("Emails" vs "E-mail", "Leden Aanmeldingen" vs "Leden").
- Tests are Karma/Jasmine. There is no visual-regression tooling, so CSS-only
  changes are gated by `npm run build` plus two small deterministic Node scripts
  introduced in Phase 0. Do not claim a CSS change is "tested" when it is only built.

### Assumptions

1. Dutch is the only UI language. All new copy is Dutch.
2. No backend/PocketBase schema changes. Read-only queries only.
3. "50+" means: needs larger type, higher contrast, fewer choices per screen,
   obvious 48px+ targets, and reassurance ("what happens if I click this").
4. Light theme stays the default (`theme.service.ts:15-21` already defaults to light).
   Do not change the default.
5. We are allowed to restructure the top navigation, but the sidenav keeps all
   member/beheer destinations.

## Architecture / proposed approach

Introduce one readability layer — a Sass partial of tokens (`src/_leesbaarheid.scss`)
plus a `--app-font-scale` custom property driven by a tiny persisted
`LeesbaarheidService` — and route every later change through it. On top of that,
fix the four things older users hit first: contrast, type size, navigation depth,
and page structure (a shared `app-pagina-kop` that guarantees exactly one `<h1>`
and an optional "Terug" link per page). Everything else is a small, independent
edit at an already-known file path, sequenced so each step is shippable on its own.

### T0.3 Add the contrast guard script (TDD: this must fail first)

Create `scripts/check-contrast.mjs`:

```js
#!/usr/bin/env node
// Fails when a readability token pair does not meet WCAG AA (4.5:1).
// Usage: node scripts/check-contrast.mjs
import { readFileSync } from 'node:fs';

const TOKEN_FILE = 'src/_leesbaarheid.scss';
const AA_NORMAL = 4.5;

function luminance(hex) {
  const h = hex.replace('#', '');
  const channels = [0, 2, 4].map((i) => parseInt(h.slice(i, i + 2), 16) / 255);
  const lin = channels.map((c) =>
    c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
  );
  return 0.2126 * lin[0] + 0.7152 * lin[1] + 0.0722 * lin[2];
}

function contrast(a, b) {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
}

const tokens = new Map();
let source;
try {
  source = readFileSync(TOKEN_FILE, 'utf8');
} catch {
  console.error(`FOUT: ${TOKEN_FILE} bestaat nog niet.`);
  process.exit(1);
}
for (const match of source.matchAll(/^\s*\$([a-z0-9-]+):\s*(#[0-9a-fA-F]{6});/gm)) {
  tokens.set(match[1], match[2].toLowerCase());
}

const CHECKS = [
  ['link-licht', 'wit', 'link op witte achtergrond'],
  ['link-licht', 'kaart-licht', 'link op lichte kaart'],
  ['link-licht-hover', 'wit', 'link hover op wit'],
  ['knop-licht-achtergrond', 'knop-licht-tekst', 'primaire knop (licht)'],
  ['knop-donker-achtergrond', 'knop-donker-tekst', 'primaire knop (donker)'],
  ['link-donker', 'achtergrond-donker', 'link op donkere achtergrond'],
  ['tekst-licht', 'wit', 'bodytekst op wit'],
];

let failed = 0;
for (const [fgName, bgName, label] of CHECKS) {
  const fg = tokens.get(fgName);
  const bg = tokens.get(bgName);
  if (!fg || !bg) {
    console.error(`ONTBREEKT: $${fgName} of $${bgName}`);
    failed++;
    continue;
  }
  const ratio = contrast(fg, bg);
  const ok = ratio >= AA_NORMAL;
  console.log(
    `${ok ? 'OK  ' : 'FAIL'} ${label}: ${fg} op ${bg} = ${ratio.toFixed(2)}:1 (min ${AA_NORMAL})`
  );
  if (!ok) failed++;
}
process.exit(failed === 0 ? 0 : 1);
```


```ts
import { Injectable, signal } from '@angular/core';

export type TekstGrootte = 'normaal' | 'groot' | 'extra-groot';

export interface TekstGrootteOptie {
  waarde: TekstGrootte;
  label: string;
  schaal: number;
}

export const TEKST_GROOTTES: readonly TekstGrootteOptie[] = [
  { waarde: 'normaal', label: 'Normaal', schaal: 1 },
  { waarde: 'groot', label: 'Groot', schaal: 1.15 },
  { waarde: 'extra-groot', label: 'Extra groot', schaal: 1.3 },
];

const OPSLAG_SLEUTEL = 'tovedem-tekstgrootte';

/**
 * Onthoudt en past de tekstgroottevoorkeur van de bezoeker toe.
 * De schaal wordt als CSS-variabele op <html> gezet; `src/styles.scss`
 * gebruikt die in `font-size: calc(100% * var(--app-font-scale))`, waardoor
 * alle rem-maten in de app meeschalen.
 */
@Injectable({ providedIn: 'root' })
export class LeesbaarheidService {
  readonly tekstGrootte = signal<TekstGrootte>(this.leesOpgeslagen());

  constructor() {
    this.pasToe(this.tekstGrootte());
  }

  zetTekstGrootte(waarde: TekstGrootte): void {
    this.tekstGrootte.set(waarde);
    localStorage.setItem(OPSLAG_SLEUTEL, waarde);
    this.pasToe(waarde);
  }

  schaalVoor(waarde: TekstGrootte): number {
    return TEKST_GROOTTES.find((optie) => optie.waarde === waarde)?.schaal ?? 1;
  }

  private leesOpgeslagen(): TekstGrootte {
    const opgeslagen = localStorage.getItem(OPSLAG_SLEUTEL);
    return opgeslagen === 'groot' || opgeslagen === 'extra-groot'
      ? opgeslagen
      : 'normaal';
  }

  private pasToe(waarde: TekstGrootte): void {
    document.documentElement.style.setProperty(
      '--app-font-scale',
      String(this.schaalVoor(waarde))
    );
  }
}
```

### T2.2 Add the font-floor guard (test first)

Create `scripts/check-font-floor.mjs`:

```js
#!/usr/bin/env node
// Faalt wanneer een stylesheet een font-size onder de leesbaarheidsondergrens zet.
// Bestanden in scripts/font-floor-allowlist.txt zijn bekende technische schuld.
import { existsSync, readFileSync } from 'node:fs';
import { execSync } from 'node:child_process';

const FLOOR_REM = 0.875; // 14px
const ALLOWLIST_FILE = 'scripts/font-floor-allowlist.txt';

const allowlist = new Set(
  existsSync(ALLOWLIST_FILE)
    ? readFileSync(ALLOWLIST_FILE, 'utf8')
        .split('\n')
        .map((line) => line.trim())
        .filter(Boolean)
    : []
);

const files = execSync('git ls-files "src/**/*.scss"', { encoding: 'utf8' })
  .split('\n')
  .filter(Boolean);

let violations = 0;

for (const file of files) {
  if (allowlist.has(file)) continue;
  const lines = readFileSync(file, 'utf8').split('\n');
  lines.forEach((line, index) => {
    const match = line.match(/font-size:\s*([\d.]+)rem/);
    if (!match) return;
    const value = parseFloat(match[1]);
    if (value < FLOOR_REM) {
      console.error(`${file}:${index + 1}  font-size: ${value}rem (min ${FLOOR_REM}rem)`);
      violations++;
    }
  });
}

if (violations > 0) {
  console.error(`\n${violations} te kleine lettergroottes gevonden.`);
```

```ts
  /**
   * Dutch table timestamp, e.g. "10 januari 2026 om 19:30".
   * Used in management tables and print views.

  formatTableDateTime(utcString: string | null | undefined): string {

  }
```

```ts
import { Injectable, inject } from '@angular/core';

/**

@Injectable({ providedIn: 'root' })
export class MeldingService {

  }

  info(bericht: string, titel = 'Informatie'): void {

}
```

## Risks, tradeoffs, and open questions

1. **The `html.lightMode *  { color: #000000 }` universal rule** (`styles.scss:179-190`)
   is the root cause of most colour hacks in this file. This plan works *around* it
   by adding higher-specificity rules. Removing it entirely would be cleaner but
   risks regressions in ~40 components; it is deliberately out of scope. **Open
   question for the owner: schedule that cleanup as its own change?**
2. **Colour lives in three places** (`variables.scss`, `styles.scss`,
   `theme.service.ts`). This plan touches all three for every colour change, which
   is error-prone. A follow-up should delete the imperative `setProperty` calls from
   `theme.service.ts` and let CSS theme classes do the work — but that is a
   behaviour-affecting refactor and needs its own review.
3. **Text scaling multiplies every `rem`.** At "Extra groot" (1.3×) some fixed-width
   layouts may overflow: the coupon/print views (`printen.component.html`) and the
   `groep`/`productie-info` three-column layouts are the likely offenders. T10.4
   checks /agenda and /reserveren only. If print output breaks, the fix is
   `@media print { html { font-size: 12pt; } }` — do not shrink the on-screen scale.
4. **Navbar restructure is user-visible.** Regulars have muscle memory for
   "Groepen" and "Sinterklaas" in the top bar; both move under "Meer". Mitigation:
   the footer still links to everything (`footer.component.html:45+`), and the
   primary items stay in place. **Open question: is a temporary "Nieuw" hint needed?**
5. **`/reserveren` picker adds a query.** `getAll('voorstellingen', …)` reuses the
   15-minute cache in `PocketbaseService`, so the extra call is cheap. But it does
   mean the picker can show a performance that closed in the last 15 minutes; the
   existing `isPastHoursBefore(…, 8)` guard in the form still blocks booking.
6. **Bootstrap's `navbar-toggler` `aria-expanded="false"`** is hardcoded in the old
   code and kept in T4.2 because Bootstrap's JS rewrites it. If accessibility
   auditing flags it, the fix is to add `(show.bs.collapse)`/`(hide.bs.collapse)`
   listeners — not to remove the attribute.
7. **Members-only pages keep `display-1` and small fonts.** Nine beheer pages still
   use `<p class="display-1">` as a title and remain in
   `scripts/font-floor-allowlist.txt`. They are behind login, are used by ~5 people,
   and are a natural second pass. **Open question: include them in this change or a
   follow-up?** Recommendation: follow-up, because each needs its own visual check
   with real data.
8. **Toast timeout of 9s** may annoy admins doing bulk work (the same config applies
   to beheer screens). If that is a real complaint, the fix is a per-call
   `timeOut` via `MeldingService`, not a lower global default.
9. **No visual regression testing exists.** Every task with a "verify in the browser"
   table is a genuine, un-automatable gate. Skipping them is the main way this plan
   can be declared done while still looking wrong.
